  2.4 FULL LIFECYCLE — USER TO PRICE STABILIZATION
────────────────────────────────────────────────────────────────────────────────

  Phase 1: USER ONBOARDING
  ───────────────────────
  1. User acquires AU (via bonding curve or external DEX)
  2. User calls StakingPool.stake(amount)
  3. StakingPool locks AG equivalent at current ratio
  4. User receives staking position (tracked internally)
  5. Optional: User mints AVSoul NFT for 2x multiplier

  Phase 2: REWARD ACCUMULATION
  ───────────────────────────
  1. Each block: StakingPool accrues rewards at 0.00001 AG/block/base
  2. Multiplier applied: 1x-10x based on lock duration
  3. AVSoul holders get additional 2x boost
  4. User calls StakingPool.claim() or auto-compound triggers
  5. PIDController monitors total staked TVL

  Phase 3: PID ADJUSTMENT
  ──────────────────────
  1. PriceOracle reports current AG/AU price to PIDController
  2. PID calculates: error = target_price - current_price
  3. P-term: Kp * error → immediate correction
  4. I-term: Ki * integral(error) → accumulated drift correction
  5. D-term: Kd * derivative(error) → dampening
  6. PID output = emission_rate_adjustment (clamped to [1, 1000] AG)
  7. If cooldown elapsed (12 blocks), PID signals AMOEngine

  Phase 4: AMO BUYBACK / STABILIZATION
  ───────────────────────────────────
  1. AMOEngine receives PID signal
  2. Checks: cooldown (24 blocks), runway reserve (2000 AG min)
  3. Fetches TWAP from Oracle (60-block window)
  4. Verifies: max deviation < 2%, slippage < 0.5%
  5. Executes swap on AMM: AG → AU (if AG overvalued) or AU → AG (if undervalued)
  6. Max 500 AG per epoch enforced
  7. Result: price moves toward 0.2 AU/AG target

  Phase 5: FLASH BUYBACK (Periodic)
  ────────────────────────────────
  1. Every 10 rounds, FlashBuyAgent activates
  2. Executes flash loan: borrow AU, buy AG, repay, keep profit
  3. 10% of profit sent to TreasuryVault
  4. Purchased AG burned (deflationary pressure)
  5. Max single buyback: 5,000 AG

  Phase 6: PRICE STABILIZATION
  ───────────────────────────
  1. Repeated PID→AMO cycles maintain peg
  2. Staking rewards incentivize holding
  3. Buyback-and-burn creates deflationary floor
  4. Bonding curve on AU ensures reserve backing
  5. System converges to 0.2 AU/AG ± 0.5%

  2.7 GOVERNANCE FLOW
────────────────────────────────────────────────────────────────────────────────

  1. Any user with ≥10,000 AG (0.1% of supply) calls Governor.propose()
  2. Proposal enters voting_delay period (1 block)
  3. Voting period opens for 14400 blocks (~2 days)
  4. AG holders vote For/Against/Abstain
  5. Quorum must be met (4% of total supply)
  6. If passed: proposal queued in TimelockController
  7. Timelock delay: 259200 seconds (3 days)
  8. After delay: anyone can call Timelock.execute()
  9. Target function executes on destination contract

  Governance can:
  - Adjust PID params (Kp, Ki, Kd)
  - Change AMO limits (maxPerEpoch, cooldown)
